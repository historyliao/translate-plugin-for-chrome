# 延迟完成耗时文案设计

## 背景

延迟总览当前使用“平均总耗时”，API、模型和每日明细使用“总耗时”。“总耗时”没有说明这是成功请求的平均值，也容易被理解为模型纯推理耗时或包含页面交互的整体耗时。

## 修改方案

- 总览标题改为“历史成功请求平均完成耗时”。
- API、模型和每日明细中的“总耗时”改为“平均完成耗时”。
- 在延迟总览下方常驻展示完成耗时、P50、P95 和最近样本范围的简短说明。
- 在 README 中补充 TTFB、TTFT、完成耗时、P50 和 P95 的详细统计口径。

“完成耗时”仍指从调用模型 API 前到有效译文完整接收的时间：流式请求以收到 `[DONE]` 为终点，非流式请求以完整响应解析并确认译文有效为终点。仅成功请求参与平均值。

## 兼容性与验证

本次只修改 Popup 展示文案、样式和 README，不修改延迟采集、聚合、存储结构和清理逻辑。执行 JavaScript 语法检查、Manifest 解析检查和 `git diff --check`。
