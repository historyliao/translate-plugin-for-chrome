# 翻译悬浮卡片视觉设计

## 背景

插件当前在用户选中英文后创建一个封闭 Shadow DOM，并在选区附近显示白色翻译框。现有容器只有边框、圆角、阴影和正文，加载、结果与错误主要依靠文字颜色区分，视觉层级较弱。流式翻译每收到一个内容片段都会重新写入整个 Shadow DOM，样式和节点也随之反复创建。

本次将悬浮框升级为简洁的 AI 翻译卡片，在不增加操作负担的前提下改善加载反馈、正文可读性、错误辨识度和深色模式体验。

## 目标

- 使用清爽卡片风格展示加载状态、译文、错误和流式中断。
- 增加紧凑的“AI 翻译”头部，建立清晰视觉层级。
- 支持系统浅色和深色模式。
- 流式响应只更新内容节点，不反复重建 Shadow DOM。
- 保持选区定位、滚动跟随、点击外部关闭和请求取消行为不变。
- 不引入外部资源、第三方库或新增配置。

## 非目标

- 不新增复制、关闭、固定、反馈或重新翻译按钮。
- 不增加主题配置、字号配置或动画配置。
- 不修改翻译提示词、API 请求、流式协议、监控和日志逻辑。
- 不修改选中文本规则和悬浮框关闭方式。
- 不修改 Popup、Options 或 Manifest。
- 不新增单元测试。

## 卡片结构

```text
┌────────────────────────────────┐
│  译  AI 翻译                   │
├────────────────────────────────┤
│  中文翻译内容……                │
│  支持多行文本和流式追加         │
└────────────────────────────────┘
```

Shadow DOM 创建一次以下结构：

```html
<section class="translation-card" data-state="loading" role="status" aria-live="polite">
  <header class="translation-header">
    <span class="brand-icon">译</span>
    <span class="translation-title">AI 翻译</span>
  </header>
  <div class="translation-body">
    <div class="loading-indicator">...</div>
    <div class="translation-content"></div>
    <div class="interruption"></div>
  </div>
</section>
```

- 头部固定显示圆形“译”图标和“AI 翻译”。
- 正文区域根据状态切换加载提示、译文或错误内容。
- 流式中断区域位于已有部分译文下方。
- 所有动态文本使用 `textContent` 写入，不拼接为 HTML。

## 视觉规范

### 尺寸

- 最大宽度：`min(440px, calc(100vw - 24px))`。
- 最大高度：`min(340px, calc(100vh - 24px))`。
- 圆角：12px。
- 头部内边距：10px 14px。
- 正文内边距：12px 14px 14px。
- 正文字号：14px，行高 1.65。
- 卡片内容超出最大高度时允许纵向滚动。

不设置固定宽度或强制最小宽度，短单词译文保持紧凑，长文本按最大宽度自然换行。

### 浅色模式

- 背景：接近纯白的浅色背景。
- 主文字：深灰色。
- 次级文字：中性灰。
- 强调色：蓝色。
- 边框：低对比度灰蓝色。
- 使用两层柔和阴影，兼顾浅色和复杂网页背景。

### 深色模式

通过 `@media (prefers-color-scheme: dark)` 自动切换：

- 背景：深灰蓝色。
- 主文字：浅灰白色。
- 次级文字：浅灰色。
- 强调色：较亮蓝色。
- 边框和阴影提高与深色网页的分离度。

不检测网页自身主题，也不新增手动主题开关。

## 状态设计

### 加载

- 头部保持“译 / AI 翻译”。
- 正文显示纯 CSS 圆形加载动画和“正在翻译…”文字。
- 颜色使用次级文字色，不显示空白结果区域。

### 结果

- 隐藏加载提示。
- 译文使用主文字色和舒适行高。
- 保留原有段落与换行，长单词允许断行。
- 流式片段直接追加到同一文本节点，卡片不重复执行入场动画。

### 错误

- 图标和标题切换为错误强调色，标题显示“翻译失败”。
- 正文使用错误文字色和浅红背景块。
- 不改变现有用户错误文案。

### 流式中断

- 已返回译文继续以正常正文样式显示。
- 下方增加带分隔线的浅红提示区域，展示原有“翻译中断”文案。
- 卡片整体不切换为纯错误状态，避免弱化已获得的译文。

## 动画与可访问性

- 卡片首次出现时执行约 140ms 的淡入和轻微上移动画。
- 流式更新不重复执行入场动画。
- 加载图标使用匀速旋转动画。
- 在 `prefers-reduced-motion: reduce` 下关闭入场和旋转动画。
- 卡片继续使用 `role="status"` 和 `aria-live="polite"`。
- 错误状态更新标题和正文，但不引入新的键盘交互。
- 浅色和深色状态均保持足够的文字对比度。

## DOM 更新策略

当前 `showOverlay()` 每次都写入 `shadowRoot.innerHTML`。修改后：

1. 第一次展示时创建 Host、Shadow DOM、固定样式和卡片节点。
2. 保存卡片、标题、加载、正文和中断节点引用。
3. 后续调用只更新 `data-state`、`textContent` 和 `hidden`。
4. 每次内容或状态变化后继续调用现有 `repositionOverlay()`。
5. `closeOverlay()` 删除 Host 时同时清空全部节点引用。

这会避免流式内容到达时反复解析 CSS 和重建节点，也避免入场动画重复触发。`escapeHtml()` 不再需要；因为动态数据只通过 `textContent` 写入，可删除该函数。

## 定位与交互兼容

- Host 继续使用 `position: fixed`、最高层级和现有 pointer events。
- 卡片继续优先显示在选区下方，空间不足时显示在选区上方。
- 继续限制在视口左右和上下 12px 安全边距内。
- 滚动和窗口缩放继续重新定位。
- 点击卡片内部不关闭；点击选区和卡片之外关闭。
- 关闭卡片、产生新选区、关闭翻译或页面离开时继续取消当前请求。
- Content Script 与 Service Worker 的 `chunk`、`done`、`error` Port 协议不变。

## 调用链和副作用

```text
选中英文
   |
   v
showOverlay(加载状态)
   |
   +-- chunk ------> showOverlay(结果状态并更新正文)
   |
   +-- error ------> showTranslationError()
   |                   |
   |                   +-- 无译文：错误状态
   |                   +-- 有译文：结果 + 中断提示
   |
   +-- 外部点击 ---> closeOverlay() ---> 取消请求并删除卡片
```

`showOverlay()` 仍由同一组调用方使用，参数语义不变。`showTranslationError()` 仍根据是否已有部分译文决定纯错误或中断展示。定位函数继续查询卡片节点计算尺寸，不改变关闭与取消的下游副作用。

## 验证计划

### 静态检查

- 执行 `node --check content/content-script.js`。
- 验证 `manifest.json` 可解析。
- 执行 `git diff --check`。
- 项目没有 Makefile，因此不执行 make 目标。
- 不执行 lint 或 test。

### 纯代码检查

- 加载、结果、错误和中断四种状态映射正确。
- Shadow DOM 只在首次展示时创建，流式片段只更新文本节点。
- 动态文本全部使用 `textContent`，不存在 HTML 注入。
- 关闭卡片后节点引用全部清理。
- 定位函数查询新的卡片 class，原定位算法保持不变。
- 浅色、深色和减少动画媒体查询完整。
- Content Script 与 Service Worker 消息协议没有变化。
- 选区关闭、请求取消和错误展示调用链没有变化。

按用户要求，本功能不使用 Chrome DevTools 或浏览器调试完成验证。

- 悬浮框具有清晰的头部、正文层级、圆角和柔和阴影。
- 加载、结果、错误和中断状态易于区分。
- 系统浅色和深色模式均有对应样式。
